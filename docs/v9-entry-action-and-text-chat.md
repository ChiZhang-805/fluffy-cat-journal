# v9：记录页按钮与「文字聊聊」微调

## 修改范围

本版基于 `ChiZhang-805/fluffy-cat-journal` 的提交
`b2617eb560d5d47490d904deb5d3523f6f0d02e0`（v8），只调整记录入口按钮和回顾文字聊天弹层。
小猫素材、动作时序、六入口、八个可放组件位置、日期补记、跨天睡眠、循环书写、庆祝与数据回顾不重做。

### 记录页底部按钮

- 六类记录的空白或未填满表单显示居中的「麦克风 + 长按向小猫倾诉」。邀请态没有向右箭头。
- 所有当前类别的文字、数字、餐次和时分字段都有合法值后，普通记录显示「完成并继续」，恢复原来的箭头。
- 专注填满后仍是「开始专注」，历史补记和编辑仍是「补记专注」「保存修改」，不改变实际业务流程。
- 清空一个字段、只填空白字符或填入无效数字时恢复邀请。`0` 这样的合法营养值不是空白。
- 照片、API Key 不参与完成度；饮食和面部都能无照片手动记录。
- 手动输入、选择餐次/时分、原生 change 自动填充、AI 回填、语言与日期变化，以及重开已有草稿都会同步状态。
- 「全部填满」用于按钮显示，不改变既有提交校验：可选营养仍可留空，短按仍按原校验提交已知内容，不为了变按钮而迫使用户猜数值。
- 文字字段状态仅在输入/回填/切换时读取并验证，不在每一动画帧反复校验；状态不变时不重写按钮 DOM。

### 两种录音布局保持区分

记录页：长按时波形和转写仍出现在上方的记录模块，底部按钮显示「松开结束」。没有把波形移进底部按钮。
回顾页：图表保持可见，语音波形仍在下方绿色长按钮内。两套录音/取消流程互相独立。

授权、等待开始、收音、整理的状态优先级高于填写完成度；忙碌时不能因为AI填了数据就闪回继续按钮。
按原规则只在用户长按时申请输入，不因为填写完成或打开表单自动录音。

### 文字聊聊弹层

- 标题左侧增加本地聊天 SVG 图标。
- 输入框下沿到发送按钮上沿留 14 个设计像素，沿用浅色圆角风格。
- 「发送图标 + 说给小猫」作为整体居中；文字为 17 px，按钮高度至少 48 px。
- textarea 多行输入、800字符上限；Enter 换行，Ctrl/Cmd+Enter 可发送，输入法合成确认不会误发。
- 空白消息不发送；重复提交最多一次；关闭后的定时聚焦不抢焦点。
- 仍使用当前板块、日期和会话的原对话链路，聊天不修改已确认记录。
- 这些样式只用于回顾「文字聊聊」，不会把其他底部面板都改成聊天框。
