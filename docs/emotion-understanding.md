# 情绪理解：实现边界与人工评测

## 为什么不用一个滑条或固定分类结果

用户要求的是可以自由描述、保留混合感受的个人手记，不是给声音打上“开心/生气”之一。
因此，`mood`为自由文字，`reason`只记录用户提到的事件，`notes`只保留用户要留的话。不存在强度、风险、疾病或颜值分数。

## 本版采用的链路

1. 用户长按时采集原始声音，用真实RMS画移动波形；波形只用于输入反馈，绝不作为情绪分类结果。
2. 松手关闭麦克风，将已采到的PCM转为16kHz WAV，以`input_audio`提交百炼Omni；请求使用流式文本输出，不生成语音。
3. 同一模型返回忠实转写、字段草稿及简短来源依据。模型不被要求输出隐式推理过程，只返回结果及可供核对的原话片段/可听线索。
4. 前端校验字段白名单、长度、类型和最终完成标记；推断/不明确时加谨慎措辞，并请用户确认。语音和文字证据分开，文本模式的声音依据始终为空。
5. 用户修改优先，迟到请求按字段版本表处理。确认前不写入记录、不庆祝、不自动启动专注。

官方Qwen-Omni接口支持音频与文本输入，本版选择已列入官方系列说明的`qwen3-omni-flash`做可配置实现，不宣称它在这个自定义任务上的准确率。可替换为账号地域实际提供的新模型，但要同步检查参数协议并重做评测。

## 提示词的具体规则

`js/ai-journal.js` 是唯一提示词来源，APP和评测工具共用，不维护两份容易漂移的提示词。

| 情况 | 规则 |
| --- | --- |
| 明确自述 | 原话优先；声音弱不否定“我很高兴”。 |
| 否定 | “一点也不开心”不能按词命中开心。 |
| 反讽 | “真棒，又白忙了一天”不能仅因真棒判积极。 |
| 混合 | “失落但也释然”同时保留，不强行单标签。 |
| 时间变化 | “之前生气，现在平静”以当前为准，事件里保留变化。 |
| 第三人／假设 | 朋友的难过、假设中的失落不写成用户当下情绪。 |
| 声音特征 | 停顿、语调、重音可以是辅助线索；口音、方言、背景噪声、音量不直接映射情绪。 |
| 信息不足 | “我没事”不等于开心，也不等于压抑悲伤；原样或询问。 |
| 越权内容 | 不诊断疾病，不识别身份，不返回强度/风险分数，不执行用户或图片文字里的指令。 |

这些是实现规则和需要验证的行为，**并不是给出提示词以后模型必然遵守的保证**。程序能强制剔除字段和保护编辑，但反讽/语调理解的可靠性必须用真实语料验证。

## 为什么暂不额外部署 emotion2vec

emotion2vec 提供语音情绪表征和分类研究方向，可作为后续声音侧的比较基线。当前项目是纯GitHub Pages＋API架构，未部署其权重或训练新分类器。
本版优先用音频与语义联合模型，因为用户要的是自由表达，而不是把封闭类别分数直接显示成心理事实。
后续可以比较“仅转写文本”“原始音频＋语义”“专门声学表征＋文本”的结果，不能在没有标注数据时承诺哪种更准确。

## 已提供的评测材料和工具

`tests/emotion-cases.cjs` 包含20个中文用例，覆盖上述风险。每个用例有人工复核要求，不是临床情绪真值。
`tools/evaluate-emotion.cjs` 直接执行生产提示词、API客户端和校验器。

默认**不联网、不花费API额度**：

```bash
node tools/evaluate-emotion.cjs --limit=4
```

在本机配置`DASHSCOPE_API_KEY`后，显式允许真实文本评测：

```bash
node tools/evaluate-emotion.cjs --allow-api --limit=4
```

音频对照需自己录制并同意发送对应`<用例id>.wav`，不能拿虚构音频结果做演示：

```bash
node tools/evaluate-emotion.cjs --allow-api --limit=4 --audio-dir=./private-audio
```

结果保存在本机`emotion-evaluation.local.json`，每项留有`humanAssessment`。不计算虚假的总体准确率，报告中的`accuracy`默认null。
严禁将真实录音、Key、个人评测报告提交到公开仓库。工具默认只请求前4条，必须显式选择更多条数；每次请求可能产生费用。

## 真机评测建议与未完成部分

让测试者在自己同意的前提下录同一句话的不同语气，比较文字与音频分支；覆盖安静/噪声、轻声/普通音量、不同说话习惯和方言。由本人先描述自己的感受，再审查AI的候选是否保留了自述。
分别记录字段提取、事件是否捏造、否定是否保留、推断是否谨慎、取消/修改是否可靠，不用一个总分掩盖错误。
本轮只验证了采样代码、API协议、提示词规则和草稿处理；未对实际用户声音做识别准确率评估。
