# v11：明确的新记录/修正记录，以及完整英文阅读层

## 1. 首页进入规则

读设备本地日历日期，只匹配同日、同类别、已经确认保存的条目。
没有条目进表单；有条目进该日回顾。尚未保存的字段与AI草稿不算。
正在进行或暂停的专注计时优先进入计时页，不因已有记录丢掉活动计时。
首页今日进度按不同类别计数，同一类有3次也只算1/6。

## 2. 用户明确控制写入

回顾菜单新增「新增记录」「修改记录」「当日记录」，保持图标+四字中文。
所有六类都可以新增或修改。新增生成独立ID；修改必须选择某一条，带回原内容。
多条选择列表展示时间和摘要，编辑保存仍使用原ID、原createdAt；updatedAt更新。
取消不保存，重复动画不新增条目。存储保留最近8次被修改前的副本（不是图片/录音）。
预期updatedAt不匹配或原ID已删除时拒绝旧快照覆盖，提示重新打开。
这是一套浏览器本地一致性保护，不是多设备服务器事务系统。

## 3. 意图理解不是写入指令

`record-intent.js` 将“下午又跑了”作为新增候选，将“刚才填错了”作为修正候选。
“早上低落，现在轻松”保留为另一时刻，而不是覆盖早上的感受。
局部关键词只负责保守初筛；不明确表达可以使用已启用的真实模型复核。
模型输出只能是 add/edit/ask/none 及候选索引，禁止创造ID或删除/批量覆盖。
日期、餐次、显式编辑对象共同缩小候选范围。明确对象有歧义时仍让用户选择。

回顾对话收到写入意图时仅出现「记录想法」入口。用户点击后选择新增或修改。
明确新建/编辑与语音含义冲突，也先确认再切模式，不悄悄改目标。
要修正一条时只提取明确提到的字段，未提及字段保留，编辑框的最后决定权属于用户。
迟到请求受取消序号与字段版本保护。回填完也不等于保存；仍需用户确认。
模型判断不是准确率保证，取消/未配置API时保留安全的手动入口。

## 4. 多条数据

运动按时长、饮食按已知营养数值、专注按实际elapsedMs汇总；休息不计入专注。
修改旧条目后从明细重算，不把新值再次叠加。
睡眠按日期+时分还原每段时间，再取区间并集：23:00—07:00和01:00—08:00共9小时。
夜间和午睡可以并存，重叠不重复。缺少可确定区间的损坏记录不伪装为0小时。
情绪/面部按时刻保留各次，主要显示最近记录，可从「当日记录」看此前变化。
不把心情或外观加成一个好坏分数。

## 5. 语言层

中文布局和现有中英混排保持。英文覆盖首页、各表单、计时、菜单、历史、偏好、回顾、
分享、静态/动态气泡、日期单位、空状态、加载与错误以及辅助阅读标签。
中文菜单保持四字，英文用自然短语；菜单独立可滚动但隐藏滚动条。

分离三层：
1. 原始确认记录：永远保留，切语言不写数据库。
2. 正在编辑的用户文字和实际转写：不被自动翻译覆盖，即使英文界面也保留原话。
3. 只读展示：使用单独英文副本，常见确定短语和单位本地翻译；陌生自由文本需真实API。

英译通过现有DeepSeek/百炼客户端执行，最少必要字段分批提交，结果只驻留页面内存。
校验数量、英文语言、原数值和时间，拒绝少条/改数字/夹中文的结果。
无Key或失败显示“Translation unavailable”，不是虚构含义或退回夹杂中文。
重新启用Key可重试；切回中文立刻恢复原始表达。英文原文或录音转写不会反写覆盖用户记录。
AI英文回复有显式约束，收到中文回复返回英文可重试提示，不直接混入英文气泡。
