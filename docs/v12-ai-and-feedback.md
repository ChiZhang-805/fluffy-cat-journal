# v12 · 语言路由与小猫反馈

## 本轮范围

在 v11 的完整应用上修改，原来的猫咪图层、六类表单、历史记录、日期补记、英文界面、图表和动画保留。
语言任务固定 DeepSeek Chat；百炼只执行用户明确提交的食物/面部照片分析。原始录音到 Omni 的整理入口关闭。

## 用户能够看到的变化

- 缺项由原小猫气泡询问，例如“运动项目还空着 / 说说做了什么呀”；不再在绿色按钮上方显示提示条。
- 网络、鉴权、余额、限流、超时、模型空回复、格式错误和听写失败各有独立受控语义码。
- 错误对白为本地中英文短句，不依赖网络或额外模型，不回显上游响应、Key或调试文本。
- 一页一到两行；较长的英文和多个核对事项按真实字宽分页。最后一页保留，下一次操作会取消旧分页。
- 普通记录语音波形仍在上方记录模块，回顾聊天波形仍在下方绿色按钮。没有新增说明面板。
- 成功回填以后仍需用户检查并确认；没有强行填满未提到的字段，没有自动保存或庆祝。

## 服务分工

|任务|执行者|
|---|---|
|声音转文字|浏览器 SpeechRecognition / webkitSpeechRecognition|
|项目、时长、备注等字段整理|DeepSeek Chat|
|情绪文本、专注估时、意图分析、翻译、回顾聊天|DeepSeek Chat|
|拍照后的食物/面部外观分析|阿里云百炼视觉模型|

两份Key同时启用不会改写路由。只有百炼Key时，普通语音会先请用户启用DeepSeek，不偷偷回退供应商。
照片Key和语言Key保存在各自客户端私有内存；没有新增本地持久化、云存储或录音上传功能。

**音频识别并不由 DeepSeek 完成。** 浏览器自身可能把录音交给其语音识别服务；应用只将已收到的转写文本发给DeepSeek。
当前语义模式不声称分析了声音中的语调、语速或真实情绪；acousticEvidence 被清空。
SpeechRecognition 并非所有浏览器均支持，也可能依赖网络，设置DeepSeek Key不会修复浏览器ASR服务不可达。

## 修复的失败链路

原始路径：百炼Omni一次返回fields和transcript → transcript为空时统一报“没听清”。
新路径：浏览器取得转写 → DeepSeek只整理fields → 独立校验并回填。

模型不再必须提供transcript，原话来自浏览器。兼容白名单字段放在模型顶层的明确结构；不猜测字段别名、不把错误JSON当有效记录。

## 可恢复性与取消

1. 麦克风授权和实际录音分开；授权晚到时释放音轨，取消不会迟到启动。
2. 长按松手后先结束输入，再等待最后一段识别结果，最多4秒。有临时尾句则保留草稿并要求核对。
3. API失败保留当前页本次转写，仅存于内存。气泡解释原因后提示“点我再试一下”。用户点击或按Enter/Space才重新提交；无需重新录音。
4. 重试与首次请求都使用字段版本快照。用户期间手动改过的字段不会被旧结果覆盖。
5. 切页、切日期、取消、更换Key后的旧响应不能回填新场景。取消和异常路径释放轨道、识别器、定时器及控制器。
6. 每次请求有总超时；仅对明确429或临时5xx、且Retry-After不超过2.5秒的DeepSeekHTTP失败最多重试一次。未知网络状态不自动重发，以免重复消费。失败仍需显式重试。
7. 回顾聊天同样保留未发送成功的文字；只有成功回复才写入会话，不改动记录数据。
8. 原话缓存仅在当前操作场景内，刷新或离开会清理，不承诺跨页面或跨设备恢复。

## 校验与边界

- JSON检查终止原因、空回复、拒绝、格式和对象类型；禁止危险原型键，限制内容长度/嵌套深度。
- 字段白名单和原有数值范围校验继续工作；部分有效信息不会因为没说备注而全部丢掉。
- 图片响应错误与音频听写错误不混为一谈。
- Key启用测试读取模型列表，不代表完整语音、图片或聊天链路已实测。
- 失败不能凭空生成示例，不能默默把低置信推测当事实。
- 没有增加TTS：小猫通过原文字气泡回应。

## 文件

`js/ai-policy.js`：固定服务边界、故障码和安全JSON检查。  
`js/cat-feedback.js`：本地化自然对白。  
`js/bubble-copy.js`：原气泡排版和逐页反馈。  
`js/deepseek.js` / `js/bailian.js`：私有Key、超时、取消、响应校验。  
`js/speech.js`：独立听写和实时音量。  
`js/ai-journal.js`：字段整理，不再依赖模型转写字段。  
`js/app.js` / `js/review.js`：版本保护、失败原话、显式重试。  
`css/refinement-v12.css`：移除旧底部错误条，不改主要布局。

## 复核方式

```sh
node --test tests/*.test.cjs
python tests/v12-browser.py
python tools/audit-comments.py
python tools/build-standalone.py ../Fluffy-Cat-v12.html
```

浏览器测试使用实际交付源码，在内存文档中装载；测试存储、网络和识别回调是**明确的替身**。
当前执行环境的本地URL导航被阻止，因此没有把内存文档测试表述为真实网站访问。
没有调用用户个人Key、真实麦克风、真实摄像头或付费模型，也未执行iPhone/Safari/Windows部署端到端实测。
图中听写与回填来自人工测试数据，不是一次真实用户录音成功的证据。
旧Omni成功、底部toast详情的3项测试按新需求改成“禁用旧路径、气泡内反馈”，未静默跳过。

最终结果见更新包verification/result-summary.json及各原始日志。不能用自动化测试保证外部识别与模型永远不出错。
